# Security and privacy

## Supported version

Security fixes target the latest code on `main`. Update before reporting a bug.

## Reporting a vulnerability

Use this repository's **Security → Report a vulnerability** option when private
reporting is available. If it is unavailable, open an issue asking the maintainer
to enable private reporting; do not include exploit details or sensitive data.
Never post passwords, tokens, environment files, library exports, or private
deployment URLs in public issues, pull requests, screenshots, or logs.

## Deployment model

This is a single-user app. Anyone with its app password can read and modify the
same library. It is not a multi-tenant service. Use a unique, long password and
random session/cron secrets generated by the setup wizard. Use HTTPS for hosted
instances and deployment access protection where available. The password gate
does not implement a distributed login rate limiter; use hosting-level access
controls or rate limiting for an internet-accessible instance.

Supabase secret/service-role keys belong only on the server. The migrations
enable RLS and revoke public-role table/view access. Apply every migration before
using real data; do not grant browser clients access to the database.

Spotify tokens, your MusicBrainz contact identifier, library snapshots, folders,
and tags are private instance data. Environment profiles and backups are ignored
by Git. MusicBrainz enrichment sends album lookup metadata and the configured
contact identifier to MusicBrainz. The manual OAuth fallback displays a refresh
token once; keep that browser window private and prefer the setup wizard, which
saves the token directly to the local environment file.

## Before making a fork public

Review all branches, tags, commit authors/messages, issues, pull requests,
release assets, Actions logs/artifacts, and deployment metadata. Removing a file
from the latest commit does not remove it from Git history. Rotate any exposed
credential first, then follow
[GitHub's sensitive-data removal procedure](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
Keep private deployment links out of repository metadata and disable deployment
status/comment publishing if the hosting integration would expose them again.
